# The Workshop — Skill Bookshelf & Agent NPCs

## Context

The Claude Code RPG teaches Claude Code concepts (skills, agents, hooks, plan mode, sub-agents, automation) through a Stardew Valley-style pixel art game. The village is "broken" and players fix it by learning these concepts.

**This feature adds Layer 2: The Workshop** — an in-game interface where players visualize, create, and manage real `.claude/` artifacts. The game reads and writes actual files on disk. Changes in-game = real changes to `.claude/` files. The village IS your `.claude/` folder made physical.

**Why now:** The game currently teaches through quests and NPC dialogue, but players can't see or interact with the actual Claude Code configuration that powers the game. The Workshop makes the meta connection tangible — "the NPC you're talking to was generated by this skill."

**Future layers** (not in this spec): Marketplace/Trading Post for community sharing, Hooks/Clocktower for automation visualization, Memory/Library, Plan Mode/Architect's Table.

## MVP Scope

### In Scope
- Skill Bookshelf overlay (visualize and browse `.claude/skills/`)
- Skill Editor (create/edit skills with freeform text, templates, and hints)
- Vite middleware API for reading/writing `.claude/` files
- Zustand store extension for claude data
- Agent NPCs spawned from `.claude/agents/` in the world

### Out of Scope (Deferred)
- Hooks/Clocktower building
- Memory/Library building
- Plan Mode/Architect's Table
- Marketplace/Trading Post (Layer 3)
- Two-way file watching (external edits updating game in real-time)
- Automation/loop visualizations

## Architecture

```
.claude/ (filesystem)          Vite Middleware API           Game (Kaplay + React)
┌─────────────────┐           ┌──────────────┐             ┌──────────────────────┐
│ skills/          │◄──read───┤ GET /api/     │◄──fetch────┤ Zustand store        │
│   brand-and-tone/│──write──►│   claude/     │──response─►│   claudeData slice   │
│   generate-npc/  │          │   skills      │            │                      │
│ agents/          │          │   agents      │            │ React overlays:      │
│   orchestrator   │          └──────────────┘             │   <Bookshelf />      │
│   critic         │                                       │   <SkillEditor />    │
│   implementer    │                                       │                      │
└─────────────────┘                                       │ Kaplay entities:     │
                                                          │   Agent NPCs (world) │
                                                          └──────────────────────┘
```

**Data flow:**
1. World scene loads → Zustand fetches skills and agents from middleware
2. React overlays (Bookshelf, Editor) read from store
3. Kaplay world scene reads agent data from store, spawns NPC entities
4. Player creates/edits a skill → PUT to middleware → writes SKILL.md → store refreshes

**Best practice justification:** HTML/DOM overlays for complex UI (bookshelf, editor) is the established pattern in HTML5 game development. Phaser, PixiJS, and Kaplay communities all recommend DOM for text-heavy, scrollable, interactive UI panels. Canvas is for gameplay entities. This hybrid approach is already used in the game (dialogue box, HUD, quest journal are React overlays).

## Component 1: Vite Middleware API

**File:** `src/server/claude-api.ts`
**Integration:** Plugs into Vite's `configureServer` hook in `vite.config.ts`

### Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/claude/skills` | GET | Lists all skills. Scans `.claude/skills/*/SKILL.md`, parses YAML frontmatter, returns array of `{ name, description, path }` |
| `/api/claude/skills/:name` | GET | Returns full content of one skill's SKILL.md |
| `/api/claude/skills/:name` | PUT | Creates or updates a SKILL.md. Creates the directory if needed. Body: `{ content: string }` |
| `/api/claude/agents` | GET | Lists all agents. Scans `.claude/agents/*.md`, parses name/role from content, returns array of `{ name, role, description, path }` |

**No DELETE endpoint** — too destructive for a teaching game.
**No auth** — localhost only, dev server context.

### Parsing

Skills: Read YAML frontmatter between `---` delimiters for `name` and `description`. Category is determined by a hardcoded mapping in the middleware (e.g., `game-architecture` → "Game Design", `brand-and-tone` → "Assets & Art", `test-wave` → "Workflow"). New skills default to "Custom" category. A future version could add a `category` frontmatter field.

Agents: Parse the markdown heading for name, extract role from the first paragraph or a structured comment.

## Component 2: Zustand Store Extension

**File:** `src/store/game-store.ts` (extend existing store)

### New State

```typescript
interface ClaudeData {
  skills: SkillEntry[]
  agents: AgentEntry[]
  isLoading: boolean
  isBookshelfOpen: boolean
  isEditorOpen: boolean
  editingSkill: string | null  // skill name being edited, null for new
}

interface SkillEntry {
  name: string
  description: string
  category: string
  path: string
  content?: string  // loaded on demand when reading/editing
}

interface AgentEntry {
  name: string
  role: string
  description: string
  path: string
  dialogueLines: DialogueLine[]  // parsed from agent .md content
}
```

### New Actions

- `fetchSkills()` — GET /api/claude/skills, updates store
- `fetchAgents()` — GET /api/claude/agents, updates store
- `fetchSkillContent(name)` — GET /api/claude/skills/:name, loads full content
- `saveSkill(name, content)` — PUT /api/claude/skills/:name, then refreshes skills list
- `openBookshelf()` / `closeBookshelf()` — toggle overlay, pause/resume game input
- `openEditor(skillName?)` — open editor for existing or new skill
- `closeEditor()` — return to bookshelf

### Input Management

When `isBookshelfOpen` or `isEditorOpen` is true, Kaplay keyboard input is disabled. On close, input is re-enabled. This follows the same pattern as the existing dialogue system.

**Closes:** `K` key or `Esc`

### Book Spines

- Each skill is a book with a colored spine (color by category: purple=game, green=assets, brown=workflow)
- Varied heights for visual interest
- CSS clip-path geometric icons (no emojis — per UI/UX Pro Max guidelines)
- Hover: book slides up 6px
- Selected: book slides up 10px, gold border glow
- `+` slot: dashed border, opens editor on click

### Detail Panel

- Parchment-textured background (`#f0e6d0`)
- Shows: skill name, description, file path
- Two buttons: READ (opens read-only view) and EDIT (opens skill editor)
- Appears when a book is clicked/selected

### Keyboard Navigation

- Arrow keys browse between books
- `E` opens the selected skill for reading
- `N` opens editor for a new skill
- `Esc` or `K` closes the bookshelf

### Features

- **Freeform text editor**: `<textarea>` styled with monospace pixel font, line numbers, syntax highlighting for YAML frontmatter
- **Templates sidebar**: Clickable templates that populate the editor with starter content. Categories: Blank, Code Style, Generator, Workflow, Testing
- **Help sidebar**: Expandable sections explaining what a skill is, the SKILL.md format, and examples from existing skills
- **Contextual hints**: Floating tooltip that changes based on cursor position — explains frontmatter fields, suggests content for sections
- **Save button**: Writes to `.claude/skills/<name>/SKILL.md` via PUT endpoint. Creates directory if new. Refreshes store. Shows success feedback. Returns to bookshelf with new book visible.
- **Filename**: Auto-generated from the `name` frontmatter field (kebab-case)

### Templates

Each template provides a full SKILL.md starter:

| Template | Content |
|----------|---------|
| Blank | Just frontmatter skeleton (`---\nname:\ndescription:\n---\n`) |
| Code Style | Frontmatter + "When to Apply" + "Rules" + "Examples" sections |
| Generator | Frontmatter + "Output Format" + "Steps" + "Quality Checklist" sections |
| Workflow | Frontmatter + "When to Use" + "Process" + "Checklist" sections |
| Testing | Frontmatter + "Test Strategy" + "Conventions" + "Verification" sections |

## Component 5: Agent NPCs

**Spawning:** On world scene load, after `fetchAgents()` completes, spawn one NPC entity per agent in `claudeData.agents[]`.

**Entity creation:** Uses the existing `createNPC()` function from `src/game/entities/npc.ts` with agent-specific data:

### Agent Mapping

| Agent File | NPC Name | Role | World Position | Sprite |
|------------|----------|------|----------------|--------|
| orchestrator.md | The Orchestrator | Village Leader | Near town center | Robed figure, gold crown accent |
| critic.md | The Critic | Quality Inspector | Near market/inspection area | Red beret, dark coat |
| visual-critic.md | The Visual Critic | Art Inspector | Near an easel/art area | Purple artist hat |
| implementer.md | The Implementer | Blacksmith | Near forge/workshop | Leather apron, hammer |
| knowledge-keeper.md | The Knowledge Keeper | Librarian | Near library area | Blue robe, glasses |

### Dialogue

Each agent's `.md` file content is parsed into dialogue lines that explain their role in accessible, in-game language:

- **Orchestrator**: "I coordinate the team. When there's a big task, I break it down and assign pieces to each specialist. One thing at a time — that's how we avoid chaos."
- **Critic**: "My job is to find every flaw. I test everything — visuals, interactions, rough edges. Nothing ships until I say it's polished."
- **Implementer**: "Point me at a problem and I'll fix it. I read the issue, read the code, make the smallest change that solves it. No more, no less."
- **Knowledge Keeper**: "I maintain the village records. When someone learns something new, I write it down so we never forget. Skills, patterns, lessons — all captured."
- **Visual Critic**: "I judge with my eyes. Would this embarrass us if someone saw it? That's my only question. Pixel-perfect or it goes back."

Interaction uses the existing dialogue system (`openDialogue(lines)`).

### Sprites

Initial implementation: recolor existing NPC sprites (mayor/blacksmith) with distinct palettes per agent. Each agent gets a unique color scheme matching their role. Future: dedicated agent sprite sheets.
